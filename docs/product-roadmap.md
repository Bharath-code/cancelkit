## Build Philosophy

1. **Each phase ships something usable.** No phase leaves the app broken. After any phase, you can demo what you've built.
2. **Infrastructure before features.** Phase 0 sets up everything so feature work is fast and clean.
3. **Magic moment first.** OAuth → 10-second branded preview lands at the end of Phase 1 — before the live widget exists. The preview is also the sales asset, so it leads.
4. **Test as you go.** Every task's Notes end with a verification step. Billing-touching code additionally gets a Stripe-CLI replay check.
5. **Progressive enhancement.** Simplest working version first, polish layered in Phase 4.
6. **Review before proceeding.** Push each completed phase as a PR and let a review agent (e.g. [CodeRabbit](https://coderabbit.ai)) review it before starting the next phase. Billing-state code (Phases 2–3) especially: external review is the cheap insurance.
7. **Billing state is sacred (product-specific).** Any task touching Stripe mutations must implement idempotency and read-back verification in the same task — never "add verification later."
8. **Protect the ten seconds (product-specific).** Any change to the OAuth → preview path must keep p95 under 10s; check the PostHog timing event after touching it.

## Agent Session Guide

### How to Use This Roadmap with Your Coding Agent

1. **Start a session:** Give your coding agent the phase prompt at the beginning of each phase.
2. **Read selectively:** Each phase lists its Reference sections — the specific parts of the PRD and vision doc needed for that phase. The agent should read only those sections, not the entire documents.
3. **Let it work:** The agent reads the roadmap, finds the first unchecked task, implements it, and marks it complete.
4. **One session = one phase (ideally):** If you need to stop, the agent resumes from the first unchecked task.
5. **Push a PR for review:** When a phase is complete, push the work as a PR and let a review agent (e.g. [CodeRabbit](https://coderabbit.ai)) review it before starting the next phase. For Phases 2–3 (live billing mutations), treat review as mandatory, not optional.
6. **Need more context?** If a task references a section not in the phase's Reference sections, read just that section on demand.

### Session Tips

- **Don't read everything:** The PRD is long by design; the Reference sections are the index. Loading full documents wastes context.
- **Don't skip tasks:** Ordering is dependency ordering. TASK-027's billing gate depends on TASK-043 replacing a TODO — the comments mark these seams.
- **Verify after each phase:** Each phase ends with a verification-sweep task; do not skip it — it is the phase's definition of done.
- **Update the status line:** After completing tasks, update `**Status:** X/62 tasks complete` and `**Current Phase:**` in this file's header.
- **Stripe test mode until TASK-060.** Nothing touches live mode before the cutover task.
- **design.md gap:** Run the Design System skill early (ideally before TASK-007). If tokens land later, reconcile the `/* TODO design.md */` placeholders as a small follow-up task in whatever phase you're in.
