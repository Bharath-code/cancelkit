# CancelKit Audit — 2026-09-25

Scope: full code audit at commit `cdb4de9` + market/competitor research (web, Sep 2026) + exec lenses + pivot decision.
Labels: every figure carries a source or is marked **ASSUMPTION**. Confidence: H / M / L.

## ⚠ Contradicts `validation-report.md`

The validation report (2026-07-02) rests on: *"Churnkey, ProsperStack, and Chargebee Retention vacate the $39 tier; DIY lives there instead."* As of Sep 2026 that is **false**:

- ≥7 products now sell a Stripe cancel flow at $0–$79/mo: Unchurn $29, SaveMRR $19→$39, ChurnNote $29, ChurnWard $29, SubJolt free/$99, Raaft free/$79, AcornRetain freemium (Stripe App), Recurflux $59.
- Stripe's own customer portal already ships a retention coupon + cancellation-reason capture, and Stripe announced native subscription **pause** (public preview) at Sessions 2026.
- AcornRetain installs from the Stripe App Marketplace with **scoped permissions** — it has already solved the trust barrier the report named as the #1 fatal flaw, better than CancelKit's `read_write` OAuth.

The "empty tier" wedge is gone. Speed-to-install alone isn't a moat when competitors claim 5–15 minutes too.

## TL;DR

1. **Code is a solid MVP** (fail-open design, idempotent Stripe writes, 1.37 KB widget). But it has 1 critical dependency CVE, 3 high-severity security/trust issues, and an MRR calculation bug that inflates the product's core ROI number.
2. **The market moved.** The low-price tier is crowded and Stripe is shipping the core features natively. A standalone $24–39 cancel widget is now a commodity (H).
3. **You haven't run the test yet.** 0 outreach, 0 OAuth attempts, 0 revenue; 7 tasks are blocked on credentials. Every business number below is an assumption until then.
4. **Recommendation: reposition, don't pivot yet.** Fix the trust and security issues (≈3 days). Rebuild as a Stripe App with scoped permissions. Aim at AI-native / usage-billed SaaS, where churn is worst (40% GRR). Run the 30-founder test within 21 days.
5. **Kill criteria:** fewer than 3 paying installs from ≥30 personalized outreaches by **2026-11-20** → stop CancelKit, or pivot to the dunning-plus-cancel "retention suite" only if calls show involuntary churn is the pain.

**Single next action:** fix the four Critical/High security items below, then create the Stripe test-mode credentials that unblock the 7 blocked tasks.

### Security

| Sev | Finding | Where | Fix | Effort |
|---|---|---|---|---|
| **Crit** | `next@16.2.10` has a critical advisory: *"Middleware / Proxy bypass in App Router"*. Auth gating lives in `proxy.ts`. Convex still re-checks the token, so the impact is limited to the page shell, but it's still a critical CVE. | `package.json`, `src/proxy.ts:8` | `npm i next@16.3.6 eslint-config-next@16.3.6`; `npm audit fix` | S |
| **High** | **Sandbox bypass on a public endpoint.** `sandbox:true` skips both the billing gate and HMAC, yet still calls Stripe for any `cus_…` id. With the public `ck_pub_` key (visible in page source), anyone can read any customer's plan name, price and currency, and spam `cancelSessions` rows. No legitimate caller uses it: the preview uses `cancelSessions.start`. | `convex/http.ts:98,128,144` | Delete the `sandbox` branch from `/widget/session` (and `?sandbox=1` in `embed/page.tsx:50`) | S |
| **High** | **HMAC never expires and travels in a URL.** `HMAC(customerId)` is valid forever and is put in the iframe `src` query string, so it ends up in logs and history. Anyone holding it can open a session and **cancel that customer's subscription**. | `convex/lib/hmac.ts:34`, `widget/src/loader.ts:103-108` | Sign `customerId.timestamp` (≤10 min TTL) or issue a short-lived server token; pass it via `postMessage`, not the URL | M |
| **High** | **Trust claims don't match the grant.** Landing page: *"Scoped OAuth: we can pause… We cannot issue refunds."* OAuth requests `scope=read_write`, i.e. full account access. The security page also claims *"no `*` targets"*, but the embed does `postMessage(msg, "*")`. | `oauth/start/route.ts:19`; `page.tsx:129`; `security/page.tsx:49-60`; `embed/page.tsx:27` | Say "our code only calls X; the token Stripe issues is broad". Real fix: Stripe App with `subscription_write`, `coupon_read`, etc. | S (copy) / L (App) |
| Med | **Resolve race (TOCTOU).** The `outcome === "open"` check and the Stripe mutation aren't atomic. Parallel `accept_offer` + `cancel` both pass and both run, because their idempotency keys differ. | `convex/http.ts:237-305` | An atomic `claimSession` mutation that flips to `resolving` before any Stripe call | S |
| Med | **Webhook failures are lost.** Errors after the ledger insert return 200, so Stripe never retries and the event is gone. | `convex/http.ts:546-550` | Delete the ledger row on failure and return 500 | S |
| Med | No security headers (CSP, `frame-ancestors`, HSTS). App pages (kill switch, secret rotation) can be framed (clickjacking). | `next.config.ts:5` | `frame-ancestors 'none'` everywhere except `/embed` | S |
| Med | CORS falls back to `*` when `APP_URL` is unset | `convex/http.ts:18` | Fail closed | S |
| Low | Logout via GET (CSRF logout); 7-day JWT with no revocation; fragile coupon error match `message.includes("coupon")` | `api/auth/logout`, `lib/session.ts`, `deflect.ts:38` | POST logout; `jti`/version; match `err.code` | S |

Done well (keep): timing-safe HMAC compare, OAuth `state` nonce, Stripe idempotency key per session, read-back verification after every write, webhook signature check before parsing, current-state fetch (not event order), PII scrub in Sentry, `autocapture:false` in PostHog.

### Correctness in the money path

| Sev | Finding | Where | Fix |
|---|---|---|---|
| **High** | `mrrCents = items[0].price.unit_amount`. This ignores interval, quantity and extra items. A $1,200/yr plan is recorded as $1,200 **MRR** (12× too high). The "saved MRR" and "Nx what you paid us" figures are the core ROI claim, so they'd be wrong. | `convex/stripe.ts:49-50` | Normalize: `Σ(unit_amount × qty) ÷ interval_months` | S |
| Med | Emails format every amount as USD and sum mixed currencies | `convex/emails.ts:22-27,104` | Use `session.currency`; group sums by currency | S |
| Med | "Cancel anyway" cancels **immediately** (`prorate:false`), so the subscriber loses paid time. ProsperStack offers period-end. It also creates refund/chargeback exposure. | `convex/deflect.ts:180` | Per-account setting, defaulting to `cancel_at_period_end` | S |
| Low | Widget status `live` never decays back once heartbeats stop | `convex/widget.ts:26-34` | Derive from `lastHeartbeatAt` at read time | S |

- `cancelSessions.stats` runs `.collect()` on every outcome row per account, reactively, on each dashboard view. That is O(sessions). Pre-aggregate counters on write. `convex/cancelSessions.ts:20-26`

### Scalability (what breaks when)

| Customers | Breaks | Where |
|---|---|---|

### Maintainability, architecture, docs, testing, CI

- Architecture: the fail-open loader (3 s handshake timeout, releases the native click) is the best idea in the codebase. **Market it.** Stripe Connect OAuth for Standard accounts is *"not recommended for new platforms"* per Stripe docs; Stripe Apps is the supported path. (H)
- Three hand-synced twin files (`constants.ts`, `widget-protocol.ts`/`types.ts`, Sentry scrub) will drift. Import from one module via a path alias.
- README is still the `create-next-app` template. Add setup, env vars, `convex dev`, and a runbook.
- Tests: 11 cases, all on pure helpers. **Zero** on `http.ts` routes, `deflect.ts`, and webhooks, where the money moves. The billing torture test (TASK-036) is still unchecked.
- CI: none. Add GitHub Actions running `tsc` + `eslint` + `vitest` + widget budget + `npm audit --audit-level=high`.

Where CancelKit is still ahead: (1) a working **branded preview built from your own Stripe data** before installing; (2) **fail-open** guarantees; (3) in-app flow with no portal redirect; (4) real-time "you just saved X" emails. All four can be copied in weeks. None is a moat. (M)

### Benchmarks (what a customer can expect)

- Cancel flows save **15–30%** of deliberate cancellations [12][16]; Churnkey reports 20–40% of otherwise-lost revenue [17]. (M: vendor-sourced)
- Offer acceptance by type: discount **53.9%**, pause **19.2%**, plan change 6.7% [17]. CancelKit shows exactly one offer, and defaults to pause, the weaker one. Consider defaulting to the coupon when one exists. (M)
- Top cancel reasons: budget 33%, low usage 31% [17].
- Involuntary churn is **20–40% of total churn** [18]. Dunning recovers 42% on average [17]; Stripe claims 55% recovered with its own tools [19]. That's a large pool CancelKit ignores.
- AI-native products: **40% GRR / 48% NRR** vs B2B SaaS median NRR 82% (ChartMogul, ~200 AI cos, Sep 2025) [20]. This is the segment that most needs retention tooling.

### Market size (bottom-up)

- Stripe Billing: **>300,000 companies**, ~200M subscriptions [21]. (M)
- ASSUMPTION: 12% are B2B/prosumer SaaS in the $5k–50k MRR band → **~36,000** companies. (L)
- ASSUMPTION: 50% are self-serve, English-speaking, and reachable → **SAM ≈ 18,000**.
- At $39/mo ($468/yr) → **SAM ≈ $8.4M ARR**. At 1% share → 180 customers ≈ **$7k MRR**.
- Read: a lifestyle-business ceiling for a pure cancel widget, not a venture-scale one. Getting bigger requires more revenue per customer (dunning, analytics) or a new segment. (M)

### Tailwinds & headwinds

- ➕ FTC "click-to-cancel" rule: vacated Jul 8, 2025, but the FTC reopened rulemaking with an ANPRM on Mar 13, 2026, and ~30 states have auto-renewal laws [22][23]. CancelKit's always-visible "cancel anyway" is **compliant by design**, which is a real selling point.
- ➕ AI-product churn wave [20]; NRR is the valuation metric.
- ➖ Stripe is building natively: retention coupon, reasons, pause (preview) [13][15].
- ➖ AI coding makes DIY faster every quarter. Claude Code can build this widget in an afternoon.
- ➖ Stripe discourages OAuth for new Connect platforms and recommends Stripe Apps [24].

## Part 3 — Exec lenses (they disagree on purpose)

### PM
- ICP (revised): Stripe-billed SaaS at $10k–100k MRR with **≥20 cancels/month**, prioritizing AI/usage-billed products. At $5k MRR, ~1 save/month is too thin (validation report's own math).
- JTBD: "When someone clicks cancel, give me one fair shot to keep them and tell me why they left, without my engineers or my trust at risk."
- RICE top 5:
  1. Fix the MRR normalization bug (R 100% × I 3 × C 100% ÷ E 0.5 = **600**)
  2. Period-end cancel option (100% × 2 × 90% ÷ 0.5 = **360**)
  3. Offer the coupon first when one exists (discount 53.9% vs pause 19.2% acceptance) (100% × 2 × 80% ÷ 0.5 = **320**)
  4. Stripe App + scoped permissions (80% × 3 × 70% ÷ 5 = **34**)
  5. Reason-matched offers: 2 offers by reason (60% × 2 × 60% ÷ 2 = **36**)
- Cut: the monthly-receipt multiple (it amplifies the MRR bug); `/dev/*` pages in production.

### CTO
- Disagrees with PM on #4: *do not* start a Stripe App rewrite before 3 paying customers. Ship the security fixes first (≈3 days total), CI next (½ day), then money-path tests (2 days).
- 90-day plan: wk 1 security + MRR fix + CI; wk 2 torture tests with Stripe test keys; wk 3–4 go live with outreach; month 2 pre-aggregated stats + indexed webhook lookups; month 3 Stripe App only if outreach shows OAuth drop-off above 50%.
- Build vs buy: keep Convex. Use Stripe's native pause API once it's GA instead of `pause_collection`.

### CFO
- Disagrees with CMO on spend: **$0 paid acquisition** until 10 paying customers.
- Unit economics (ASSUMPTION): ARPA $24–39; gross margin **~92%** (Stripe 2.9% + Billing 0.7% + $0.30/charge + $0.60/customer infra); fixed infra ~$65/mo (Vercel Pro $20, Convex, Resend, domain).
- CAC: ~20 founder-hours per customer via personalized outreach (30 outreaches → 3 customers × ~2 h each). At a $50/h opportunity cost that's **$1,000 CAC** vs LTV ≈ $39 × 0.92 ÷ 5% churn = **$718**. **LTV:CAC < 1 on founder time.** It only works if self-serve or marketplace installs arrive without outreach.
- Pricing options: (a) flat $39; (b) tiered by cancel sessions ($29 / 100, $79 / 500) like ProsperStack; (c) **performance: 10% of saved MRR for 6 months, $19 minimum**. It aligns with ROI and beats "$29 flat" competitors on risk. Recommend (c) for the test, because it answers "why pay when I could DIY" with "you only pay when it works".

### CMO
- Disagrees with CFO: a $300/mo content budget from month 1 (the "churn benchmark" report) compounds; waiting until 10 customers wastes the SEO lead time.
- Positioning (new): *"The cancel flow that can't break your billing, and stays on the right side of click-to-cancel law. Pay only for what it saves."* Retire "cheaper Churnkey" and "5 minutes"; Unchurn and SubJolt already say that.

### CEO — the decision
- **Reposition and run the test. Don't pivot on untested assumptions, and don't keep building features.**
